# Interrupt setup evidence

IRQScope indexes statically named per-interrupt API callsites while it scans functions. It currently recognizes CMSIS-style `NVIC_EnableIRQ`, `NVIC_DisableIRQ`, `NVIC_SetPriority`, `NVIC_SetPendingIRQ`, and `NVIC_ClearPendingIRQ` names, including common `__NVIC_`, `HAL_NVIC_`, and `TZ_NVIC_` prefixes. A call is listed when the bounded intra-function constant analysis can recover `IRQn` from ARM argument register `r0`. For raw CMSIS `NVIC_SetPriority`, it also records a known second argument from `r1`; HAL priority APIs take preempt/subpriority arguments and are listed without treating `r1` as an encoded priority.

The dashboard's **Interrupt setup** table maps the recovered `IRQn` to vector slot `IRQn + 16`, then shows the matching vector entry when present. It labels evidence as either a recognized API name or a constant-base store summary. Double-clicking a row jumps to the callsite. JSON evidence exports include the call EA, containing function, action, IRQn, vector slot, mapped vector label, available priority argument, and evidence basis.

This is a static index of API calls and a narrow wrapper-summary fallback for stripped code. The fallback recognizes stores through direct or indexed operands when IDA's rendered operand identifies a base register whose propagated constant lies in the Cortex-M NVIC ISER, ICER, or IPR ranges. Callers can inherit an enable, disable, or priority operation summary. The callsite's `r0` is then interpreted as IRQn, so inspect this evidence basis carefully: the heuristic does not prove the helper's ABI, argument meaning, or indexed offset bounds. It does not surface direct stores themselves as events or support computed/dynamic IRQ arguments. When the SVD supplies `nvicPrioBits`, IRQScope can compare a recovered raw CMSIS `NVIC_SetPriority` argument with the BASEPRI snapshot using only implemented priority bits. The finding labels this a conditional hint: it does not establish call execution, effective enable state, overrides, or actual preemption. Runtime NVIC state and nested preemption remain unresolved. The analyzer never treats `NVIC_DisableIRQ` as a global `PRIMASK` mask: CMSIS defines it as disabling one device-specific interrupt, while `__disable_irq` sets PRIMASK globally. See the official [CMSIS NVIC API](https://arm-software.github.io/CMSIS_6/latest/Core/group__NVIC__gr.html) and [CMSIS core-register API](https://arm-software.github.io/CMSIS_6/latest/Core/group__Core__Register__gr.html).
